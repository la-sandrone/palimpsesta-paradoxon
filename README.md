# palimpsesta-paradoxon

> **Paradox 三款游戏（CK3 / EU4 / Stellaris）mod 加载机制的逆向整理**：
> 目录级覆盖语义、静默失效审计、版本迁移、`debug.log` 归因、符号表导出。
> 另附一个符号表解析器（`tools/`）与少量修正样例（只放 diff）。

名字取自重写本（παλίμψηστα）。羊皮纸被刮掉重写，旧字迹仍在底下——
mod 也一样：后加载的盖住先加载的，先加载的还在磁盘上，只是不生效、也不报错。

## 三分钟看懂

### 一、加载顺序是三层叠加

```
本体文件  ->  mod 之间（启动器顺序）  ->  mod 内部（目录名 / 文件名 字节序）
```

**每一层都按字节序排，不按语言习惯。**

- `zz_foo.txt` 排在 `pam_bar.txt` 之后，因为 `z`(0x7A) > `p`(0x70)
- 但 `ZZ_foo.txt` 排在 `a_bar.txt` **之前**，因为 `Z`(0x5A) < `a`(0x61)
- **中文文件名不是不能用，是用法固定**：CJK 字符的 UTF-8 首字节 >= 0xE0，
  永远排在 ASCII 之后 -> 天然最后加载 -> 覆盖一切 ASCII 文件
- 实例：Stellaris 的「小伞」（Kasako）mod 用 `伞ow_` 前缀，
  以及 `U+F995`（CJK 兼容表意文字，视觉上几乎不可见）做隐形前缀
- **代价：只能排最后。** 想插到中间，只能用 ASCII 前缀（`zz_` / `pam_`）

想覆盖某个文件，你的路径和文件名必须**完全一致**，且加载顺序在它之后。

### 二、覆盖分几种，失败方式各不相同

| 情形 | 结果 |
|---|---|
| 路径 + 文件名完全一致 | **整个文件被替换**（前一个等于不存在） |
| 文件名不同、同目录 | **共存**，两个都加载 |
| 同 key 的定义（如 `scripted_effect`） | **后者覆盖前者**，`database_conflicts.log` 记一行 `Overriding entry` |
| 容器里的列表字段 | **合并** |
| 容器里的单值槽位（如 `on_action` 的 `effect`） | **后者独占，前者静默丢弃** |

### 三、错误不报错

这是全篇最要紧的一句：

> **Paradox 的脚本没有编译器、没有类型检查、没有作用域校验、没有未定义字段警告。**
> **它只做一件事：数括号。**

所以：

- 字段名拼错 -> 被当成别的容器，泄漏出奇怪的东西（实例见 `AGENTS.md`）
- 作用域用错 -> 这个 trigger 永远返回假，不报错
- 本地化文件缺 BOM -> **整个文件静默失效**
- `.zip` 形式的 mod -> **从不被解压**，配置了但什么都没加载

**全都「能跑」。错误是沉默的、延迟发作的、只有拿真实存档去喂才会暴露的。**

| 章 | 一句话 |

## 证据从哪来

每一条结论都应该能回答「你凭什么这么说」。本仓库只接受三种证据：

1. **游戏文件里的路径与行号**——能打开就看到的那种
2. **`debug.log` 的原始日志行**——含时间戳与源文件行号
3. **可复现的操作步骤**——照着做能重现

拿不出这三种之一的，标「推测」或直接不写。
