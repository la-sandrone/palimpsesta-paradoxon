# 符号表归档

> **这里放的是引擎自己打印的符号表快照**，按 `游戏-版本` 分目录，**归档备查**用。
> 不是本项目生成的内容 —— 生成它的是游戏本身（见 `05-符号表导出.md`）。

---

## 为什么收录

| 用途 | 说明 |
|---|---|
| **离线查一个名字存不存在** | 「这个 trigger 是拼错了，还是这个版本根本没有？」——一条 `grep` 就能答 |
| **版本 diff 才有基准** | 想知道更新坏了什么，得有旧版本的表；等更新完再想要，就永远拿不到了 |
| **第三方检查器的误报可以核实** | 它的表是手工抄的；这里的是引擎自己打印的 |

> 本仓库先前写过「导出内容不收录」。**改这一条的理由是：它是一次性的、会消失的东西。**
> 游戏更新之后，旧版本的符号表**再也导不出来** —— 这不是「可随时重新生成」，是「错过就没了」。

---

## 归档口径

```
符号表/
├── ck3-1.20.1/            CK3 1.20.1.2，7 个文件（无 mod 未证）
├── ck3-1.21.0/            CK3 1.21.0.3，7 个文件（无 mod + 全 DLC，有证明）
├── ck3-1.21.0+unop-9.0.28/  同上 + Unop 9.0.28，**只存 3 个差异文件**（工作基线）
└── stellaris-4.5.3/       Stellaris Cygnus v4.5.3，5 个文件
```

四条规矩（第 2 条在 1.21 那份额外补了一句：**DLC 也要全开**，因为 DLC 同样是符号来源）：

1. **目录名 = `<游戏>-<版本>`**，版本取自 exe 内嵌串或 `code_revisions.log`，不取 `supported_version`。
2. **带 mod 的导出必须在目录名或 `PROVENANCE.md` 里写明**。干净基线与污染基线混在一起，这份归档就废了。
3. **原始字节不改**。不删行、不改行、不补 BOM、不转换行 —— 每个文件都给了 sha256，改了就查得出来。
4. **别把 `modifiers.log` 的 sha256 当内容指纹**。它的条目顺序**每次运行都可能不同**（实测同 build 三次三份不同字节、集合一致），只能用**集合**核对。（其余文件是稳定的。）
5. **变体目录只存差异文件**。命名 `<游戏>-<版本>+<mod>-<版本>`，只归档与基础版**不同**的文件，并在 PROVENANCE 里列出相同文件的 sha256 —— 相同的东西不必存两遍。

## 怎么用

### 查一个名字是否存在

```bash
# 例：这个 trigger 到底有没有
grep -n '^rite_has_parameter - ' 符号表/ck3-1.20.1/triggers.log

# 例：这个 effect 支持哪些 scope
grep -A6 '^add_tenet - ' 符号表/ck3-1.20.1/effects.log | grep 'Supported Scopes:'
```

### ⚠️ 前缀搜索会骗你（这条踩过，代价是误判整份表被污染）

先用 `grep -ic 'ce_'` 扫 CK3 的 `triggers.log`，得到 **76 条**，看起来像某个 mod 的符号混进来了。
但**行首锚定**之后是 **0 条** —— 那 76 条全是 vanilla 单词内部的子串：

```
reactive_advice_succession      <- 'advice_' 里的 ce_
advanced_activities             <- 'advanced_'
independence_faction            <- 'independence_'
```

同一类误判还有两个更好的例子，都在 `custom_localization.log` 里：

| 命中 | 看起来像 | 实际是 |
|---|---|---|
| `rice_wine` / `rice_cake` | RICE 这个 mod 的键 | **米酒 / 米糕**（本体宴会的食物名） |
| `tao_yuanming` | 某个 `tao_` 前缀 mod | **陶渊明**（本体人物） |

⇒ **判断污染必须行首锚定 + 看语义，不能只数前缀。**
⇒ 这条也是 `05-符号表导出.md` §4.1 那条纪律的同一个坑，只是换了个方向。

### 解析成 JSON

```bash
python3 tools/parse_script_docs.py 符号表/ck3-1.20.1 -o /tmp/symbols-ck3.json
python3 tools/parse_script_docs.py 符号表/stellaris-4.5.3 -o /tmp/symbols-sx.json
```

## 怎么补一份新的

1. 按 `05-符号表导出.md` 导出（CK3 要 `-debug_mode`；Stellaris 启动即生成）
2. **出游戏立刻复制** —— `logs/` 会在下次启动时被清空
3. 建 `符号表/<游戏>-<版本>/`，原样 `cp` 进去（不要重存，不要改换行）
4. 写 `PROVENANCE.md`：**有没有 mod** 这一项必须填，不能留空
5. `sha256sum *.log >` 记进 PROVENANCE，commit

### 归档时的一条取舍

**旧版本的目录不要覆盖。** 版本 diff 的价值全在「旧的那份还在」。
磁盘上多留 2 MB，换的是「这次更新坏了什么」这个问题永远能回答。
