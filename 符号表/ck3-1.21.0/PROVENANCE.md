## 「无 mod」的证明

导出后立刻抓的 `dlc_load.json`（原文）：

```json
{
  "enabled_mods": [],
  "disabled_dlcs": []
}
```

两件事同时成立：

| 项 | 值 | 意义 |
|---|---|---|
| `enabled_mods` | **0 个** | 没有 mod 混进符号表 |
| `disabled_dlcs` | **0 个** | **全部 DLC 启用** —— 符号没有被 DLC 开关截断 |
| `game/dlc/` 目录 | 30 个 | 已装 DLC 全在（含 All Under Heaven = `dlc022_ep4`） |

⇒ 第二条是本份归档的关键。**只关 mod 不关 DLC，符号表照样不准**：DLC 是符号的来源之一。

## ⚠️ modifiers.log 的条目顺序**不是**确定的（实测，2026-11-27）

同一台机器、同一 build（' + BT + '0066127f2f020' + BT + '）、三次导出：

| 次 | 配置 | 条目数 | 文件 sha256（前 16 位） |
|---|---|---|---|
| 1 | 无 mod | 976 | ' + BT + '2a723e499d307957' + BT + ' |
| 2 | + Unop 9.0.28 | 976 | ' + BT + 'f95a6ba0686acfb2' + BT + ' |
| 3 | 无 mod | 976 | ' + BT + '760c412038a678b9' + BT + ' |

**三次三份不同的字节，集合完全一致**（把 ' + BT + 'Tag:' + BT + ' 行排序后逐行相同）。

⇒ 结论：**顺序与 mod 无关，是 CK3 自己每次运行都可能换一个顺序。**

两个直接后果：

| 后果 | 说明 |
|---|---|
| 这份文件的 sha256 **不是内容指纹** | 同版本重新导出就会变，别拿它当「有没有被篡改」的证据 |
| 比较必须按集合 | 按行 diff 会满屏差异而实际零变化（见 ' + BT + '05-符号表导出.md' + BT + ' §4.4） |

其余 6 个文件在同一 batch 里**逐字节稳定**（三次运行、去掉 mod 变量后完全一致）。

### 旧版独有的一类（值得单独看）

```
$GEOGRAPHICAL_REGION$_development_growth          ->  改成 $GEOGRAPHICAL_REGION$_prosperity_growth
$TERRAIN_TYPE$_development_growth                ->  改成 $TERRAIN_TYPE$_prosperity_growth
add_great_building / add_special_building         ->  这条线上被 $DISTRICT_TYPE$_district_* 系列替换
```

⇒ 这一批不是「功能被删」，是**同一批概念改了名字与建模方式**。
对 mod 作者的含义：写死的旧名会静默落空（见 `02-静默失效案例.md` 案例 9）。

> **这份差异表只说明「名字层面变了什么」，不说明「行为怎么变」。**
> 后者只能实测。

## ⚠️ UI 语言会改变字节（实测）

导出里的列表字段用**本地化连接词**拼出来。本机 UI 语言 `l_simp_chinese`，所以：

| 文件 | 非 ASCII 行数 | 例 |
|---|---|---|
| `modifiers.log` | **198** | `Use areas: character， province，以及 county` |
| `triggers.log` | 2 | `Traits: Valid DLCs: West Slavic Attire， Tours and Tournaments，...` |

⇒ 同一版本、同一配置，**换 UI 语言导出会得到不同字节**（那 200 行变成 `, and ...,`）。
⇒ 所以跨归档比对之前，先确认两边 UI 语言一致；不一致的地方全是逗号，不是内容。
