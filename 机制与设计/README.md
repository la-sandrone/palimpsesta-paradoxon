> 它们不是教程 —— 教程会告诉你结论；这里留下的是**怎么把结论逼出来**，包括搞错的那几步。

## 一、这批文档在证明什么

四条写作纪律，每一条都能在下面的文件里找到实例：

| 纪律 | 具体做法 | 反例（本仓库自己踩过） |
|---|---|---|
| **结论挂出处** | 每个断言后面跟着 `文件:行号`、日志行、或可复现步骤 | 没有出处的猜测，后来大多被推翻 |
| **错了要留痕** | 保留「上一节错在哪」这种小节，不删改历史 | 抹掉错误过程，等于把下次踩坑的机会也抹掉 |
| **没测就标没测** | 写「未测定」「推定」，不写成事实 | 一个未验证的推断被引用三次就会变成「常识」 |
| **机制与史实互校** | 游戏机制若把 A 文明的结构套到 B 文明，要能指出来并说清代价 | 只讲「游戏里怎么打」，就发现不了设计错位 |

最后一条是这批文档里最有辨识度的部分：**引擎机制是形式，历史结构是约束**。
两者对不上时，问题往往不在玩家理解、也不在引擎，而在设计者选错了参照系。
