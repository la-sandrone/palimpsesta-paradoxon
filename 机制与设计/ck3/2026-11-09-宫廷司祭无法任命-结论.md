# 结论

> **性质**：排查结论（含四次自我更正） · **游戏**：CK3
> **归属**：CC BY-SA 4.0（见仓库 `LICENSE`）
> **适用版本**：以文中标注为准 —— 引擎改了，结论就可能过期
> **说明**：路径已占位，工坊 ID 保留（用于定位对象）；不含他人作品内容

## 表层原因：一个 Faith scope 效果放进了 rite 块

error.log:71290（首次运行）：

    [jomini_effect.cpp:784]: Inconsistent effect scopes (rite vs. faith)
      infile: common/on_action/lamps_on_game_start_actions.txt line: 279

第 279 行是 add_tenet = tenet_elf_syncretism。add_tenet 是 Faith scope，
放进 rite:byzantine_rite = { } 不合法。Rite scope 的正确写法是 add_rite_tenet
（本体 scripted_effects/pam_effects.txt:8170 有先例）。

且 tenet_elf_syncretism 属于 Elf Destiny（workshop 3114064450），
当时那份 playset 没启用它（dlc_load.json 里没有该 id），即使改对也是未知 tenet。
→ 已移除。

修掉后 Inconsistent effect scopes (rite vs. faith) 归零
（只剩别的 mod mgr_scripted_effects.txt:258/259/276 同类问题，与本 mod 无关）。

## 深层原因：rite_has_parameter 读的是缓存参数，不是教义列表

修掉作用域后 4 条 change_rite_doctrine 全部生效，但红字依旧。

存档取证（见 证据/存档取证.txt）：

| 对象 | 实例教义列表 | rite_has_parameter = clerical_appointment_fixed |
|---|---|---|
| roman_rite（天主教） | 含 spiritual_fixed_appointment | true |
| byzantine_rite（拜占庭） | 含 temporal_appointment，无任何 fixed | true ← 错 |

即：change_rite_doctrine 更新了教义列表（存档与 UI 都可见），
但没有重算 rite 的 parameter 集。参数集是建礼时按
「rite_type + 父 religion + faith」算好的，之后只改列表不改参数。

clerical_appointment_fixed 原本来自
common/religion/religion_types/00_christianity.txt 的
doctrine_clerical_succession_spiritual_fixed_appointment，
一旦算进参数集就再也下不来 —— 所以 rite 层怎么改 doctrine 都无效。

判定链（本体）：

    council_positions/00_council_positions.txt:583-588  can_fire
    → scripted_triggers/00_councillor_triggers.txt:179  can_appoint_own_court_chaplain_trigger
    → rite = { NOT = { rite_has_parameter = clerical_appointment_fixed } }

council_positions/_council_positions.info 明确 can_fire 的作用域是
「council owner character」，即检查玩家本人的礼 —— 对象选对了，判据选错了。

## 修复

新增 mod/Suiginton/common/scripted_triggers/zzzz_suiginton_councillor_triggers.txt，
覆盖 can_appoint_own_court_chaplain_trigger，把判据从 parameter 换成
rite_has_doctrine（读的就是那份实例教义列表）：

    rite = {
        NOT = { rite_has_doctrine = doctrine_clerical_succession_spiritual_fixed_appointment }
        NOT = { rite_has_doctrine = doctrine_clerical_succession_temporal_fixed_appointment }
    }

等价性：
- byzantine_rite：列表里两种 fixed 都没有 → 放行（本次目标）
- roman_rite：列表含 spiritual_fixed → 照旧拦下（与本体一致）
- 完全没有 succession 教义的礼：两种 fixed 都没有 → 放行（与本体一致）
- 1066+ 本体给基督徒设 conditional（on_action/game_start.txt:2514-2518）
  → 无 fixed → 放行。这一条与本体当前实际行为不同，
  但与 rite 教义 override 的文档语义一致（rite_types/_rite_types.info：
  「Rite doctrines override parent-religion and faith doctrines from the same doctrine group」）

## 未验证项

1. 覆盖 vanilla scripted trigger 是否被引擎采纳（后加载者获胜）—— 本次未实机验证。
   若失效，error.log 会出现 can_appoint_own_court_chaplain_trigger 相关重复定义提示。
2. 上面第 4 条等价性推论（1066+ 场合）未实测。
3. rite_has_doctrine 是否读实例合并列表：间接证据是本体
   on_action/yearly_on_actions.txt:1953 用 rite = { rite_has_doctrine = doctrine_imperial_anointment }，
   而 imperial_anointment 只在 religion 层声明、由礼继承 ——
   若只读静态列表该判定将恒假，属本体 bug，不可能。

# 第二轮实测（2026-11-09 晨）

## 1. 时点证据：不是「第二天/下个月才结算」

- 867.2.3（推进满一个月）仍拦；
- 重新读档仍拦。

结论：参数不是延迟重算，而是**建礼时一次算死**（假说 A 成立，B 排除）。

## 2. 主教席坐的是普世牧首

内阁「主教」格是 **印纳提俄斯**（character 13818）。存档里：

    rite_type=byzantine_rite ... head_of_rite=13818
    13818={ first_name="Ignatios" rite=6 ... }

即该礼的宗教首脑本人。因果链：

    religion 层 spiritual_fixed
      → rite 没有 clerical_appointment_ruler 参数
      → councillor_court_chaplain.auto_fill 成立（NOT rite_has_parameter = clerical_appointment_ruler）
      → 首脑自动入席，玩家选不了
      → can_fire / can_reassign 双双拦下，两段红字

注意 1.20 修好了「东罗马帝国牧首不是普世牧首、另生造一个帝国主教」的老 bug，
所以现在首脑直接坐进主教席。这不是新 bug，而是把老 bug 修掉后暴露出的既有规则。

## 3. 保加利亚对照不成立

保加利亚国王同样任免不了主教：斯拉夫礼（slavic_rite）也继承 religion 层的
spiritual_fixed，本来就在拦截范围内。
因此该测试**不能**用来判断 trigger 覆盖是否生效，只能说明规则通用。

## 4. 本轮改动

| 文件 | 作用 |
|---|---|
| common/religion/rite_types/zz_suiginton_byzantine_rite.txt | **主修法**：静态副本，建礼时 parameter 就算对 |
| common/scripted_triggers/zzzz_suiginton_councillor_triggers.txt | 保险：从「整体换判据」收窄成「只对 byzantine_rite 例外」 |
| mod/Suiginton/UPSTREAM.json + _maintain/check_upstream.py | 上游清单与一致性校验（泛化后取代 resync_byzantine_rite.py） |

## 5. 待验

1. 重启后内阁能否「开除 / 指派」主教；
2. error.log 是否出现 byzantine_rite 的 duplicate 提示（副本是否被采纳）；
3. 若静态副本生效，可删掉 scripted_triggers 那个文件，只留一处真相源。

## 6. scripted_triggers 覆盖无效（已实测排除）

01:11 提交的版本覆盖了本体的 can_appoint_own_court_chaplain_trigger：

    rite = {
        NOT = { rite_has_doctrine = doctrine_clerical_succession_spiritual_fixed_appointment }
        NOT = { rite_has_doctrine = doctrine_clerical_succession_temporal_fixed_appointment }
    }

06:44 启动的那一局带着这份覆盖。玩家切到保加利亚国王测试：

    70382 = {  # Boris I
        864.1.1 = { rite = byzantine_rite }  # Baptised by clergy from Constantinople
    }

Boris I 在 867 同样是拜占庭礼，教义列表里同样没有两种 fixed，
按理两个角色都该放行。结果**两人都被拦**，且 error.log 里既没有
Unknown trigger 也没有重复定义提示。

⇒ 结论：在 1.20 上覆盖本体的 scripted trigger **不被采用**（无论文件名排序如何）。
   该文件已删除，避免留下「以为有保险」的假象。

## 7. 因此当前只剩一条路

common/religion/rite_types/zz_suiginton_byzantine_rite.txt —— 静态副本。
变量唯一：下次启动的结果可以干净地归因于它。

判读：

| 结果 | 含义 | 下一步 |
|---|---|---|
| 能开除/指派 | 静态副本被采纳，parameter 在建礼时就算对 | 收工 |
| 仍不行 + 日志有 duplicate | 引擎「先到先得」，副本被丢弃 | 只剩改 religion 层（会连带天主教），需拍板 |
| 仍不行 + 无任何提示 | 副本也没被采纳 | 换注入点：history/faiths 或直接改 00_rite_types.txt |

> 补充（同一晚）：这条不是新规律，而是 AGENTS.md §3 里 FIOS 家族的实例——
> `common/scripted_triggers` 与 `events/` 同族，**先处理的赢**。
> 旁证：`database_conflicts.log` 从不记录 scripted_triggers（该轮该文件为 0 字节），
> 说明它不是 database，走脚本层 key-value 语义。
>
> 由此得到一条更一般的结论：**FIOS 意味着 mod 永远赢不了 vanilla**
> （本体文件名 `00_*` 在 ASCII 序里天然最前）。改本体行为只剩两条路：
> 静态复制本体定义（进 database 的 LIOS 逻辑），或 on_game_start 用 effect 改状态。

## 8. 第三轮：参数绑在 faith 层，只能绕开（走 B 方案）

文档依据（本体自带）：

- `_doctrine_types.info` 的 Triggers 一节只承诺两种查询：
  「Used in rite scope: rite_has_doctrine」「Used in faith scope: has_doctrine_parameter」
  —— 本体满地用的 `rite_has_parameter` **没有文档**。
- `_faith_types.info:36-37`：礼层在同一 doctrine group 里**确实**优先（教义列表如此，存档已验证）。
- `_religion_types.info:26`：religion 的 doctrine「can be overridden by putting a different doctrine
  in the group in the specific faith」—— 合法覆盖层级是 **faith**，不是 rite。

实测：`database_conflicts.log` 记录静态礼副本已生效
（`Overriding entry 'byzantine_rite' ... zz_suiginton_byzantine_rite.txt line: 9`），
但参数与 auto_fill 均未改变 ⇒ 参数不跟礼层走。

因此改用 B：覆盖 `councillor_court_chaplain` 数据库条目（466 行 → 480 行），
在 can_fire / can_reassign / can_change_once 三处加 `rite = rite:byzantine_rite` 例外。
不碰宗教，爆炸半径 = 一个职位 + 一个礼。

历史依据：867 年巴西尔一世废佛提乌、复立印纳提俄斯；877 年又请回佛提乌。
这一年主教确由君主任命，本体按 1066 年罗马的分期建模并不适用于此。

## 9. 重大更正：第 6 节「scripted_triggers 覆盖无效」结论作废

06:36–06:44 那一局带着宽版 trigger 覆盖，用户报告仍失败。
但真正的证据在 TAO（3343175673）身上：

- 它覆盖了 `councillor_court_chaplain`（`zzz_tao_council_positions.txt:911`），
  文件名 `zzz_tao_` 排在 `zz_suiginton_` 之后 → **TAO 获胜**。
- 而 TAO 的这个块**根本不调用** `can_appoint_own_court_chaplain_trigger`，
  自己内联了 `faith = { NOT = { has_doctrine_parameter = clerical_appointment_fixed } }`。

⇒ 我们改的那个共享 trigger **从未被执行过**。失败原因不是 FIOS，是死代码。
⇒ 「CK3 的 scripted_triggers 是 FIOS」这个断言目前**没有证据**，已从 AGENTS.md 撤下。
⇒ 另：06:53 那一局运行时，trigger 文件已在 06:52:05 被删除（游戏 06:53:20 启动），
   那一局对 trigger 覆盖没有参考价值。

## 10. 真正的判据链（最终）

    councillor_court_chaplain（TAO 版本获胜）
      → faith = { NOT = { has_doctrine_parameter = clerical_appointment_fixed } }
      → 作用域是【faith】，不是 rite
      → basil 的 faith = christian_faith，参数来自 religion 层 spiritual_fixed
      → 礼层（byzantine_rite）怎么改都影响不到 faith 参数

要修，只有两条：
  A. 改 christian_faith 的教义（连带天主教，方向错）
  B. 覆盖 councillor_court_chaplain，且文件名必须排在 `zzz_tao_` 之后

且 B 必须基于 **TAO 的块**而不是本体的块——否则会丢掉 TAO 对
on_get_position / on_fired_from_position / on_lose_position 的改写。

## 11. 更正：纯净本体测试不是有效判据

我曾提出「跑无 mod 模式看拜占庭能否换主教」作为判别 TAO 是否为阻力的判据。**该设计无效。**

原因：`common/religion/religion_types/00_christianity.txt:31` 明写

    doctrine = doctrine_clerical_succession_spiritual_fixed_appointment

`byzantine_rite` 父级链 = `christian_faith` → `christianity_religion`，
所以纯净本体里拜占庭礼**天然**就是 spiritual_fixed（不可开除），与天主教同源。

⇒ 纯净本体必然「仍拦」。把它当「判据成立」是循环论证：
   「TAO 是阻力」和「本体本来就这样」两个假设预测同一结果。

### 真正有效的判据

要问的是「我们的覆盖在 TAO 缺席时是否生效」，所以实验条件是：**关掉 TAO，保留我们的 mod**。

| 结果 | 结论 |
|---|---|
| 能换 | 我们的文件本身正确，只是输给 `zzz_tao_` 的排序 → 走 B2（基于 TAO 的块 + 改名 `zzzz_`） |
| 仍不能换 | 我们的文件本身有问题，需重新检查判据位置 |

纯净本体只能给出一个信息：**红字不是 mod 引入的**，本体设计如此 —— 这一点静态即可确认，无需实测。

## 12. 再更正：原版有「请求新牧首」路径，门槛是 piety_level >= 3

第 11 节说「原版设计就是不可开除」，不准确。原版是：

- 内阁 `can_fire` / `can_reassign` 拦住 → **不能把牧首当雇员开除**
- 但另有互动 `request_realm_priest_replacement_interaction`（`pam_interactions.txt:2304-3049`，746 行）
  → **向教会申请换人**，走原版候选池 + 5 年冷却

门槛（`pam_interactions.txt:2461`）：

    custom_tooltip = {
        text = piety_level_or_external_puppet_req_tt
        OR = {
            exists = puppet:external_theological_agent_puppet
            piety_level >= 3
        }
    }

巴西尔一世 867 年刺杀米海尔三世登基，piety_level 必然很低；
而他登基后的第一批动作之一就是换牧首（废佛提乌、复立印纳提俄斯）。
游戏把「给篡位者合法性」的动作卡在他没时间积累的「个人虔诚」上 ——
这是把授职权之争的西方模型（虔诚换谈判资格）套到拜占庭（机构权力）。
