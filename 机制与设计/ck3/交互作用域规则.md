## 各段落的根作用域

| 段落 | 根作用域 | 说明 |
|---|---|---|
| `is_shown` | **无根** | 只有 `scope:actor` / `scope:recipient` |
| `is_valid` | **无根** | 同上 |
| `is_valid_showing_failures_only` | **无根** | 同上 |
| `is_shown_showing_failures_only` | **无根** | 同上 |
| `ai_will_do` | **root = actor** | 文档原文 "Root is the actor" |
| `ai_accept` | **root = recipient** | 文档原文 "Root is the recipient" |
| `ai_potential` | **已废弃** | 文档："Deprecated - all interactions should use is_available instead" |

## 推论（关键）

> **在 `is_*` 段里裸写 character-only trigger 一定是 bug。**
> 因为那里根本没有根作用域，裸用拿到的是 `none`。

报错形态：

```
Error: is_ai trigger [ Wrong scope for trigger: none, expected character ]
```

而在 `ai_will_do` / `ai_accept` 里裸写是**合法**的（有根）。

## 实例（TAO 1.20 适配）

```paradox
is_valid_showing_failures_only = {
	scope:actor = { ... }          # 38 行：包对了
	trigger_if = {
		limit = {
			is_ai = yes            # ❌ 裸用，拿到 none
			...
			scope:recipient = {
				is_ai = yes        # ✅ 53 行：包对了
```

修法：`scope:actor = { is_ai = yes }`。

同一文件里 `ai_only_liege_modify_vassal_contract_admin_province_interaction` 有同样的写法，一并修。

## 静态扫描的陷阱（实测记录）

我写了一个粗筛器找「`is_*` 段内、`scope:` 块外裸用 character-only trigger」，
在 TAO 上命中 7 处，**全是误报**。两个原因：

### ① `any_*` 迭代器也会建立作用域

```paradox
any_pool_character = {
	limit = {
		is_close_family_of = scope:actor    # ✅ 合法，this 已经是角色
```

只跟踪 `scope:` 块会漏掉迭代器，于是把它误判成「无根裸用」。

### ② `scope:x ?= {` 用的是 `?=`

正则 `^scope:[a-z_]+\s*=\s*\{` 匹配不到 `scope:x ?= {`，
于是 `scope:secondary_recipient ?= { any_secret = ... }` 被误判。

## 结论

> **静态粗筛不可信，日志才是判据。**
> 真正的检查器必须同时跟踪：
> 1. `scope:` 块（含 `?=` / `|=` 等所有比较符）
> 2. `any_*` / `every_*` / `random_*` / `ordered_*` 迭代器的 `targets`
> 3. 每条 `event_target` 链路的类型
>
> 这三项缺一个，误报率就会高到不可用——
> 而误报会直接摧毁工具的可信度。
