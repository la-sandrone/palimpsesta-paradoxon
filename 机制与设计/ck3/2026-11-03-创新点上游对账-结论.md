## 两个错误的性质不同（关键）

### ① `innovation_baliffs_bailiffs` —— 抄了 **asset 显示变体名**

它**不是**一个 innovation 的 ID，而是 `innovation_baliffs` 的**显示名变体**：

本体 `game/common/culture/innovations/00_early_medieval_innovations.txt:435` 起：

```paradox
innovation_baliffs = { # Magistrates in-game
    ...
    asset = {
        trigger = { OR = { has_cultural_pillar = heritage_frankish ... } }
        icon = @leadership_1
        name = innovation_baliffs_bailiffs   # ← 只有这一行，不是定义
    }
    asset = {
        trigger = { ... heritage_latin ... }
        name = innovation_baliffs_latin
    }
}
```

**迷惑点**：本地化里有 `innovation_baliffs_bailiffs` → 简中「执达吏」/ 英文「Bailiffs」，
所以照着本地化抄名字就会抄到这个变体名。注释写「执达吏」正是这么来的。

- 正确 ID：`innovation_baliffs`，简中名「治安法官」
- 该 innovation 在法兰克/中德意志/西德意志/伊比利亚/布立吞/盖尔文化特性下**显示为「执达吏」**
- ⇒ 想表达「执达吏」，用 `innovation_baliffs` 即可，显示名会按文化自动变

### ② `innovation_development` —— 只是**漏了后缀**

本体没有无后缀的 `innovation_development`，只有 `_01` ~ `_04`：

| ID | 简中名 | 时代 | 文件:行 |
|---|---|---|---|
| `innovation_development_01` | **公共工程** | tribal | `00_tribal_innovations.txt:202` |
| `innovation_development_02` | 社区治理 | early medieval | `00_early_medieval_innovations.txt:305` |
| `innovation_development_03` | 城市化 | high medieval | `00_high_medieval_innovations.txt:395` |
| `innovation_development_04` | （未核实） | late medieval | `00_late_medieval_innovations.txt:406` |

mod 注释写「公共工程」，与 `_01` 的简中名**完全一致**。且 mod 里已引用 `_02`、`_03`，
⇒ 原意应是想补齐 `_01`，写漏了后缀。

## 修法

在 `lamps_on_game_start_actions.txt` 里替换（7 个文化块各 1 处）：

| 原 | 改为 | 影响行号 |
|---|---|---|
| `innovation_baliffs_bailiffs` | `innovation_baliffs` | 18, 48, 79, 110, 141, 170, 200 |
| `innovation_development` | `innovation_development_01` | 24, 55, 85, 117, 147, 177, 207 |

⚠️ 替换第二个时**必须带词边界**，否则会误伤 `_02` / `_03`。
`_` 是单词字符，所以 `sed 's/= innovation_development\b/= innovation_development_01/g'` 安全。

> ⚠️ 踩坑记录：一开始给出的是 `sed -i 's/A/B/g' 's/C/D/g' file` 形式 ——
> **错的**。sed 只接受一个 script 参数，第二个 `s///` 会被当成文件名，
> 报「无法读取 s/= innovation_development...」，而 `-i` 已经改掉了第一个文件 ⇒ **半修改状态**。
> 正确写法：`sed -i 's/A/B/g; s/C/D/g' file` 或分两次 `-e` / 分两次执行。
> 本次靠 `git status` 立即发现（7 处已改 / 7 处未改），未造成损失。
