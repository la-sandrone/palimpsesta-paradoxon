# 修复示例

这个目录只放 **diff**，不放整包。

## 为什么只放 diff

| 类型 | 放什么 | 理由 |
|---|---|---|
| 本项目原创的模板 | 完整的新文件 | 是自己写的，没有权属问题 |
| **第三方 mod 的修正** | **只有 diff** | 上游有明确作者、可能仍在维护。只发布「改了什么」，不重新分发它的内容 |
| 大型 / 仍在维护的 mod | **一个文件都不放** | 一旦有人问「这是谁的」，答不上来的是我 |

> 版权的风险来自「有明确的、可主张的权利人」——不是来自「有没有人维护」。
> 「上游三年没更新」不等于「放弃版权」，除非作者明确声明过。

## 文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `01-延迟结算模板.patch` | 原创模板 | `on_action` 的 `effect` 与 `on_actions` 是并发的；需要确定先后时用延迟结算（见 `01-覆盖语义.md` §七） |
| `02-字段名修正.patch` | 第三方，仅 diff | 未知字段会被当成容器，泄漏出幽灵条目（见 `02-静默失效案例.md` 案例 3） |
| `03-软依赖配桩.patch` | 第三方，仅 diff | 解析期缺符号时给一个中性桩（见 `04-日志定位方法.md` §四） |

## 使用前必读

1. **行号与上下文来自当时的现场，上游可能已经改过。** 这些补丁是**模板**，不是可以直接 `git apply` 的成品。
2. 应用前先确认目标文件当前内容（行号会漂）。
3. 改完做字节级复查：BOM、换行符（见 `06-编码与渲染.md` §六）。

## 归属与撤回

`02` 与 `03` 涉及上游 mod 的文件内容。这里只发布**修改点**，不发布被修改文件的任何完整副本，
也不主张对原始内容的任何权利。

**如原作者或权利人对此有异议，请提 issue，我会立即删除。**

这不是免责声明，是一个可执行的撤回承诺。
